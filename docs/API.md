# RepoPilot — API Design

Base URL: `http://localhost:4000` (dev). All routes under `/api/v1` are JSON.
Every request/response body is defined by a Zod schema in `packages/shared/src/schemas/` and those schemas are the single source of truth for both validation and TypeScript types.

## Conventions

- **Auth**: `Authorization: Bearer <API_KEY>` on all `/api/v1/*` routes when `API_KEYS` is configured. Health endpoints are unauthenticated. (Day 1: header is parsed and validated only if `API_KEYS` is set; single-tenant.)
- **Ids**: UUID v7 (time-ordered) generated by the API.
- **Errors**: 
  ```json
  { "error": { "code": "REPO_NOT_FOUND", "message": "Repository does not exist or is not accessible", "requestId": "…", "details": {} } }
  ```
  `code` is a value of `ErrorCode` (closed union). Zod failures return `400` with `code: "VALIDATION_ERROR"` and `details.issues`.
- **Request id**: `x-request-id` is echoed or generated; present in every log line.
- **Pagination**: `?limit=50&cursor=<opaque>` on list endpoints; responses include `nextCursor | null`.
- **Provenance**: every issue/patch/test object includes `source: "ai_inference"`; every verification object includes `source: "observed"`. Clients must render them differently.

## Decision: REST + polling, not GraphQL or WebSockets (MVP)
- *Why*: a handful of resources with an obvious hierarchy; polling every 2 s on a single run is trivial load; REST is easiest to test with `supertest` and to script with `curl`.
- *Alternative*: GraphQL (flexible queries) / WebSockets (push).
- *Rejected because*: no client-side query flexibility is needed; push can be added as SSE on `GET /runs/:id/stream` without changing the resource model.
- *Tradeoff*: slightly chattier clients; acceptable at MVP scale.

## Health

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/health` | none | Liveness. Always `200 {"status":"ok","service":"api","version":"…"}` if the process is up. |
| GET | `/ready` | none | Readiness. Checks PostgreSQL (`SELECT 1`) and Redis (`PING`). `200` when all ok, `503` with per-dependency status otherwise. |

The worker exposes the same two endpoints on `WORKER_HEALTH_PORT` (default 4001), where `/ready` additionally reports Docker daemon reachability once the sandbox runner exists.

## Runs

### `POST /api/v1/runs` — create a run
Request:
```json
{
  "repoUrl": "https://github.com/owner/repo",
  "ref": "main",
  "options": {
    "maxIssues": 10,
    "createPullRequest": false,
    "allowLifecycleScripts": false
  }
}
```
- `repoUrl`: required, must match `^https://github\.com/[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+(\.git)?/?$` or a `/tree/<ref>` form. Normalised server-side.
- `ref`: optional branch/tag/SHA; defaults to the repository's default branch, resolved during `ingest`.
- `options`: all optional, defaults shown.

Response `202 Accepted`:
```json
{ "run": { "id": "…", "status": "queued", "stage": "ingest", "repoUrl": "…", "owner": "owner", "repo": "repo", "ref": "main", "createdAt": "…" } }
```
Side effects: inserts `runs` row; enqueues job `{runId, stage}` with job id `${runId}__ingest` on queue `pipeline`.
Errors: `400 VALIDATION_ERROR`, `400 INVALID_REPO_URL`, `429 RATE_LIMITED`.

### `GET /api/v1/runs/:id` — run summary
```json
{
  "run": {
    "id": "…", "status": "running", "stage": "analyze",
    "repoUrl": "…", "owner": "…", "repo": "…", "ref": "main", "commitSha": "abc…",
    "errorCode": null, "errorMessage": null,
    "counts": { "issues": 4, "patches": 4, "validatedPatches": 3, "verifications": 2 },
    "createdAt": "…", "startedAt": "…", "finishedAt": null
  }
}
```
`status ∈ queued | running | completed | failed | cancelling | cancelled`.
`stage ∈ ingest | manifest | select_context | analyze | generate_patches | validate_patches | generate_tests | verify_baseline | verify_patches | finalize`.

### `GET /api/v1/runs` — list runs
Query: `limit`, `cursor`, `status`. Returns `{ runs: RunSummary[], nextCursor }`.

### `POST /api/v1/runs/:id/cancel`
`202 { run }` with `status: cancelling`. Idempotent. `409 RUN_TERMINAL` if already finished.

### `GET /api/v1/runs/:id/events` — timeline
Query: `after=<eventId>` for incremental polling.
```json
{ "events": [ { "id": 12, "stage": "ingest", "level": "info", "type": "stage_completed", "message": "Snapshot abc… (312 files, 4.1 MB)", "data": {}, "createdAt": "…" } ] }
```

## Results

### `GET /api/v1/runs/:id/snapshot`
Returns `repository_snapshots` row: `commitSha`, `fileCount`, `totalBytes`, `ecosystem`, `manifest` (paths only unless `?includeManifest=full`).

### `GET /api/v1/runs/:id/issues`
```json
{ "issues": [ { "id": "…", "source": "ai_inference", "severity": "high", "category": "bug", "confidence": 0.82,
  "title": "…", "explanation": "…", "filePath": "src/x.ts", "lineStart": 40, "lineEnd": 52, "evidence": "…", "patchId": "…" } ] }
```

### `GET /api/v1/runs/:id/patches` and `GET /api/v1/runs/:id/patches/:patchId`
Patch object:
```json
{ "id": "…", "issueId": "…", "source": "ai_inference", "status": "validated",
  "rationale": "…", "filesTouched": ["src/x.ts"], "diff": "--- a/src/x.ts\n+++ b/src/x.ts\n…",
  "validation": { "ok": true, "checks": [ { "name": "paths_exist", "ok": true }, … ] },
  "outcome": "improved" | "unchanged" | "regressed" | "inconclusive" | null,
  "verification": { "baselineId": "…", "patchedId": "…" } }
```
`GET …/patches/:patchId.patch` returns `text/x-patch` for download.
`outcome` is computed by `finalize` from observed verification runs only; it is `null` until then.

### `GET /api/v1/runs/:id/tests`
Generated tests: `{ tests: [ { id, patchId, path, framework, source: "ai_inference", content } ] }`.

### `GET /api/v1/runs/:id/verifications`
```json
{ "verifications": [ {
  "id": "…", "kind": "baseline" | "patched", "patchId": null, "source": "observed",
  "status": "completed" | "timed_out" | "infra_error",
  "phase": { "install": { "exitCode": 0, "durationMs": 41230 }, "test": { "exitCode": 1, "durationMs": 9120 } },
  "testSummary": { "total": 120, "passed": 118, "failed": 2, "skipped": 0, "parser": "junit" } | null,
  "command": "pnpm test -- --reporter=junit",
  "imageDigest": "sha256:…", "stdoutTail": "…", "stderrTail": "…",
  "startedAt": "…", "finishedAt": "…" } ] }
```
No field in this object is ever populated from model output.

### `POST /api/v1/runs/:id/pull-request`
Request: `{ "patchId": "…" }`.
Preconditions: run `completed`; patch `validated`; patch `outcome ∈ improved | unchanged`; GitHub App installed on repo.
Response `202 { pullRequest: { id, status: "creating" } }`; on completion `GET /api/v1/runs/:id/pull-requests` shows `{ number, url, headBranch, status: "open" }`.
Errors: `409 PATCH_NOT_VERIFIED`, `403 GITHUB_FORBIDDEN`, `404 GITHUB_APP_NOT_INSTALLED`.

## Rate limiting
Per API key: 30 run creations / hour, 600 reads / minute (Redis token bucket). `429 RATE_LIMITED` with `Retry-After`.
